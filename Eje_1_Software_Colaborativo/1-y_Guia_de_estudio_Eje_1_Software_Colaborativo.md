# Guía de estudio Eje 1: Software colaborativo

## Idea central del eje

Desarrollar software no es solamente programar. También implica organizar archivos, documentar, guardar versiones, compartir cambios y dejar evidencia del proceso de trabajo.

Durante este eje trabajamos con herramientas y prácticas que ayudan a ordenar proyectos y colaborar con otras personas.

---

## Ítems principales para repasar

### 1. Organización de archivos y carpetas

- Crear carpetas y archivos desde la interfaz gráfica y desde la terminal.
- Reconocer rutas, nombres de archivos y estructura de un proyecto.
- Mantener una carpeta de trabajo ordenada.
- Usar subcarpetas para separar archivos según su función.

### 2. Uso inicial de terminal

- Usar comandos básicos como `pwd`, `ls`, `cd`, `mkdir`, `cat`, `mv` y `rm`.
- Comprender que la terminal permite trabajar sobre las mismas carpetas que se ven en el explorador.
- Interpretar resultados simples de los comandos.

### 3. Automatización inicial

- Comprender que un script guarda una secuencia de instrucciones.
- Crear y ejecutar scripts simples en Batch.
- Comparar la lógica de Batch y Bash como formas de automatizar tareas.

### 4. Herramientas colaborativas

- Usar documentos o planillas compartidas para registrar información.
- Trabajar con otros respetando acuerdos de edición.
- Reconocer el historial de versiones en documentos compartidos.

### 5. Markdown y documentación

- Crear archivos `README.md`.
- Usar títulos, listas, enlaces, código y estructura básica de Markdown.
- Documentar un proyecto de manera clara.

### 6. Visual Studio Code

- Abrir una carpeta de proyecto en VS Code.
- Usar el explorador de archivos y la terminal integrada.
- Crear y ejecutar archivos simples dentro de un proyecto.

### 7. Sistema de control de versiones

- Comprender para qué sirve un sistema de control de versiones.
- Diferenciar archivo, proyecto, repositorio, commit e historial.
- Entender las tres zonas de Git: área de trabajo, staging y repositorio local.

### 8. Git local

- Usar comandos básicos: `git init`, `git status`, `git add`, `git commit` y `git log`.
- Crear un repositorio local.
- Guardar cambios con mensajes de commit claros.
- Revisar el historial del proyecto.

### 9. GitHub y trabajo remoto

- Diferenciar Git y GitHub.
- Crear o usar una cuenta de GitHub.
- Aceptar una invitación a un repositorio.
- Editar archivos desde GitHub o `github.dev`.
- Reconocer commits realizados en la plataforma.

### 10. Trabajo colaborativo con repositorios

- Clonar o abrir un repositorio de trabajo.
- Crear una rama para modificar sin tocar directamente `main`.
- Hacer cambios, commit, push y Pull Request.
- Explicar la diferencia entre guardar, commit y push.

---

## Conceptos clave

**Archivo:** unidad básica de información, por ejemplo `README.md`, `saludo.py` o `notas.txt`.

**Carpeta:** espacio donde se guardan archivos y otras carpetas.

**Proyecto:** conjunto organizado de archivos y carpetas que tienen un objetivo común.

**Repositorio:** carpeta de proyecto controlada por Git, con historial de cambios.

**Git:** herramienta (programa) que permite guardar versiones de un proyecto.

**GitHub:** plataforma online para alojar y compartir repositorios.

**Commit:** versión guardada del proyecto en el historial de Git.

**Push:** acción de subir commits locales a un repositorio remoto.

**Pull Request:** propuesta para revisar cambios antes de incorporarlos a la rama principal.

## Preguntas para repasar

1. ¿Por qué conviene ordenar los archivos de un proyecto?
2. ¿Qué diferencia hay entre una carpeta común y un repositorio Git?
3. ¿Para qué sirve `git status`?
4. ¿Qué hace `git add`?
5. ¿Qué guarda un commit?
6. ¿Qué diferencia hay entre Git y GitHub?
7. ¿Por qué puede ser útil tener un archivo `README.md` en un proyecto?
8. ¿Qué diferencia hay entre guardar, commit y push?
9. ¿Por qué conviene trabajar en una rama antes de modificar `main`?
10. ¿Qué evidencia puede mostrar que un grupo trabajó en un repositorio?
